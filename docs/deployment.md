# Deployment Guide

This document outlines the deployment lifecycle for the Makerspace backend.

## 1. Environment Segregation

### Local Development
- Handled entirely via `supabase start`.
- No live secrets required (use dummy `WEBHOOK_SECRET` and `RESEND_API_KEY` in `supabase/.env.local`).
- Migrations apply automatically.
- See `docs/local-development.md` for full instructions.

### Staging
- A separate Supabase project (`makerspace-staging`).
- Used to verify migrations and frontend integration before production.
- SMTP rate limits should be lifted or configured with a test provider to avoid Auth blocks.

### Production
- The live University of Ruhuna Supabase project (`makerspace-production`).
- **Strictly locked down.** CLI access requires `SUPABASE_ACCESS_TOKEN`.

---

## 2. CLI Authentication & Project Linking

Before deploying to Staging or Production:
1. **Login:** `npx supabase login` (Provides access token)
2. **Link:** `npx supabase link --project-ref YOUR_PROJECT_REF`
   - *Never commit the `supabase/.temp/` folder generated by this step.*

---

## 3. Database Migrations
Always push migrations sequentially.
```bash
npx supabase db push
```
**Rollback Considerations:** 
Supabase CLI does not cleanly support automated `down` migrations. If a migration introduces a breaking change:
1. Immediately create a new migration (`supabase migration new revert_X`) containing the exact inverse SQL.
2. Push the revert migration.
3. Do NOT attempt to rewrite production migration history.

---

## 4. Edge Function Deployment

The `process-notifications` function handles email delivery asynchronously.

**Set Required Secrets:**
```bash
npx supabase secrets set RESEND_API_KEY="YOUR_RESEND_API_KEY"
npx supabase secrets set WEBHOOK_SECRET="YOUR_WEBHOOK_SECRET"
```

**Deploy the Function:**
```bash
npx supabase functions deploy process-notifications
```
*Note: The `supabase/config.toml` file automatically ensures `verify_jwt = false` is applied during deployment.*

---

## 5. Database Webhook Configuration

After the Edge Function is deployed, wire the database to invoke it:
1. Go to **Database > Webhooks** in the Supabase Dashboard.
2. **Name:** `Process Notifications`
3. **Table:** `notification_queue`
4. **Events:** `Insert`
5. **Type:** HTTP Request
6. **URL:** `https://[YOUR_PROJECT_REF].supabase.co/functions/v1/process-notifications`
7. **Method:** `POST`
8. **Headers:**
   - `Content-type`: `application/json`
   - `x-webhook-secret`: `YOUR_WEBHOOK_SECRET` *(Must match the secret set in Step 4 exactly).*

---

## 6. Frontend Integration
The frontend application (`raven` branch) only requires two public values to connect:
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_PUBLISHABLE_KEY`

These are safe to embed in the frontend build. They do **not** bypass RLS.

---

## 7. Production Checks
Before announcing a release:
1. Verify the PostgREST cache is not stale (`NOTIFY pgrst, 'reload schema';` in SQL editor).
2. From `backend/`, run `node scripts/backend_diagnostics.js` against the production URL to verify connectivity and cache freshness.
3. Ensure Auth rate limits (e.g., 3 emails/hour) are configured appropriately for the expected university user load.
